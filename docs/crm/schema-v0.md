# CRM Schema v0

## Purpose

This document defines the first CRM schema for the AI-Native GTM Engine.

The CRM is designed to support audience ownership across newsletter subscriptions, content access, future vendor intake, job opportunity intake, and broader ecosystem signals.

Version 0 is intentionally lightweight but structured to expand over time.

## Design Principles

The CRM should:

- preserve marketing-owned audience data
- separate people, companies, and signals
- support future enrichment and segmentation
- allow additional intake pathways over time
- remain simple enough to implement in Airtable v0

## Core Tables

Version 0 includes three core tables:

1. People
2. Companies
3. Signals

## Table — People

The People table stores individual audience and contact records.

| Field | Type | Description |
|------|------|-------------|
| person_id | text / formula | Logical identifier for the person record |
| email | email / text | Primary unique identifier for the contact |
| first_name | text | Given name of the contact |
| last_name | text | Family name of the contact |
| role | single select | Role category of the individual |
| learning_interest | single or multi-select | Area of interest within GTMStack content |
| company_name_raw | text | Raw company name entered by the user during signup |
| company_id | linked record (Companies) | Reference to the associated company record |
| signup_source | single select | Source channel where the signup occurred |
| signup_timestamp | date/time | Timestamp of the signup event |
| status | single select | Lifecycle status of the contact |
| notes | long text | Additional notes or context |

## Table — Companies

The Companies table stores organisations associated with people, vendors, sponsors, or job posters.

| Field | Type | Description |
|------|------|-------------|
| company_id | text / formula | Logical identifier for the company |
| company_name | text | Canonical company name |
| website | url / text | Company website |
| company_stage | single select | Company maturity stage |
| industry | single select or text | Industry classification |
| country | single select or text | Geographic location |
| company_type | single select | Type of organisation in the ecosystem |
| notes | long text | Additional notes or context |

## Table — Signals

The Signals table captures activity and events generated by people and companies within the GTM ecosystem.

| Field | Type | Description |
|------|------|-------------|
| signal_id | text / formula | Logical identifier for the signal |
| signal_type | single select | Type of event captured |
| person_id | linked record (People) | Person who generated the signal |
| company_id | linked record (Companies) | Associated company |
| source | single select | System or channel that generated the signal |
| timestamp | date/time | When the signal occurred |
| related_asset | text | Content, event, or asset associated with the signal |
| metadata_json | long text | Flexible structured metadata for future signals |
| notes | long text | Additional notes or context |

## Example Signal Types

Examples of signal_type may include:

- newsletter_signup
- content_access
- vendor_interest
- job_submission
- referral
- event_registration

## Relationship Model

The CRM schema follows a simple relational structure:

People → Companies → Signals

Relationship rules:

- A person may belong to one company
- A company may be linked to multiple people
- A person may generate multiple signals
- A company may generate multiple signals

## Notes on Version 0

Version 0 is designed for:

- Airtable as the initial data store
- n8n as the workflow orchestration layer
- future migration to a more custom CRM if required
